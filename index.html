Assignment 1 – Introduction to Networking & Infrastructure Hands-On

OSI & TCP/IP Models • Structured Cabling • Command Line Diagnostics • Wireshark Exploration
Completed Reflection

1. My Experience Completing the Assignment

In Assignment 1, I worked through both foundational network theories and practical command-line diagnostics directly on my MacBook. I explored the structural differences between the 7-layer OSI model and the 5-layer TCP/IP model, traced the full path of structured cabling from a workstation to the ISP, and mapped out my own home network topology (Netgear R7000P router, Motorola MB7621 modem, MacBook, iPhone, and desktop PC connected via a powerline adapter in a star topology).

On the practical side, I executed network commands in Terminal—including testing loopback with ping 127.0.0.1 (which took 0.2 ms since it never leaves the machine's own network stack) and ping ucf.edu (which took 41 ms across the external network). I also ran traceroute to compare the path between Amazon (11 hops, reaching CloudFront) and UCF (9 hops, routing through MSN routers), used browser developer tools to inspect HTTP GET requests and status 200 codes, and examined Wireshark's 3-pane packet interface.

2. Key Skills & Concepts Learned

  • MAC vs. IP Addressing:
    "A MAC address identifies a network interface while an IP address identifies a device's network location. IP, unlike MAC, is used for routing across networks."
    Learned that MAC is 6 bytes, IPv4 is 4 bytes, IPv6 is 16 bytes, and port numbers are 2 bytes.
  • Encapsulation & De-encapsulation:
    "In my own words, it's packaging the data with a 'from' and 'to' towards the network layer. Transport layer produces a segment, the network layer adds an IP header to produce a packet, Data Link layer adds a MAC header/trailer to produce a frame, and Physical layer converts the frame into bits for transmission."
  • Client-Server Architecture: Understood client requests and server responses using a real-world analogy:
    "A real-life world example is fast food drive-thrus: the client (customer) requests an order of food, the server (worker) takes the order and relays the information, and the response is the food, which is the data sent back to the client."
  • Structured Cabling Hierarchy: Mapped the physical connection order: Laptop → Wall jack → Patch panel → Switch/IDF → Backbone Cabling → MDF → Demarc → ISP. Learned that horizontal UTP cabling has a maximum permanent link distance of 90 meters, while backbone cabling links IDFs to the central MDF like an elevator between floors.
  • Switches vs. Routers: A switch operates within a local network (such as 10 computers in a classroom), whereas a router is required to transport packets between different networks and connect out to the Internet.
  • Wireshark 3-Pane Architecture: Explored how Wireshark separates packet inspection into the top pane (Packet List table with packet number, time, source, destination, protocol, length), middle pane (Packet Details showing layer-by-layer breakdown: Frame, Ethernet II, IP, and protocols like IGMP), and bottom pane (Packet Bytes displaying raw hex and ASCII).

3. Challenges Faced

One challenge was understanding why certain hops in traceroute timed out and displayed asterisks (* * *) on hop 8 for Amazon and hop 9 for UCF. I learned that asterisks do not necessarily mean the network is down; they occur because intermediate routers are configured not to respond to ICMP/traceroute probes to conserve CPU resources or due to network congestion, even though traffic is passing through normally.

Another challenge was physical cabling best practices: understanding the importance of avoiding sharp bends that crush or stress UTP cables, testing cables before terminating them to the patch panel or MDF/IDF, and utilizing proper cable raceways and wire looms to prevent physical snagging.

4. Overall Takeaway & Impact

Assignment 1 gave me a solid foundation connecting physical layer reality (cables, wall jacks, patch panels, star topologies) to logical network protocols (IP addresses, subnets, routers, and client-server HTTP transactions). Being able to run diagnostic tools like ifconfig, ping, traceroute, and Wireshark directly on my own computer and see my own local IP (192.168.1.15), default gateway (192.168.1.1), and MAC address made the abstract concepts from the lecture slides tangible and intuitive.

General Reflection: Quizzes, Discussions & Lecture Slides

Chapters 1 & 2 Infrastructure Insights
Course Reflection

Reviewing the lecture slide decks (Chapter 1-2 Intro to Networking, Chapter 2-1 & 2-2 Networking Infrastructure) alongside our class discussions and quizzes highlighted several foundational principles:

  • Why Star Topology Dominates: As we discussed, a star topology requires more cable runs than a legacy bus topology, but it avoids single points of failure. If one cable is damaged, only that single workstation goes down while the rest of the network stays online. It also eliminates the bus collision domain issues.
  • The Role of the Demarc: Understanding the demarcation point as the exact physical line of responsibility between the service provider (ISP) and the customer's internal network infrastructure.
  • Layer Independence: How encapsulation ensures that higher layers (like an HTTP GET request) don't need to know whether the physical transport is Wi-Fi, Ethernet, or fiber.
