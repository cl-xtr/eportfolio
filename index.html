1 & 2. OSI and TCP/IP Models

OSI Model: Application → Presentation → Session → Transport → Network → Data Link → Physical.

  • HTTP is closest related to Application.
  • TCP is closest related to the Transport layer.
  • IP is closest related to the Network layer.
  • Ethernet frames/MAC addresses are closest related to the data link layer.

TCP/IP Model: Application → Transport → Network → Link → Physical. Unlike OSI, TCP/IP merges Presentation, Session into Application.

3. MAC vs. IP Addressing
  • MAC address is 6 bytes
  • IPv4 address is 4 bytes
  • IPv6 address is 16 bytes
  • Port number is 2 bytes

The difference between a MAC address and an IP address is that a MAC address identifies a network interface while an IP address identifies a device's network location. (IP, unlike MAC, used for routing across networks)

4. Star vs. Bus Topology

A star topology is more appropriate of a choice, even though there are more cables to manage. This is because if the bus cable is cut or interrupted, it affects all of the computers connected to it, while with a star topology, it allows for one computer to have downtime while leaving the rest of them to continue operating. On a bus, all 20 computers share one cable, which can cause subsequently more collisions and slower performance. With a star, on the other hand, each device having its own dedicated link.

6. Switches vs. Routers
  • Ten computers in the same classroom need to communicate with each other: This one would be more suitable with the switch. This is because the switch is defined as being within a network. And 10 computers are all in the same classroom, which sits in one network.
  • The classroom network needs to communicate with another network and access the Internet: A router is more appropriate for this. This is because a router is defined as transporting between networks. If the classroom network needs to communicate with another network and access the internet, then a router is required as it needs to transfer between networks.
7. Encapsulation & De-encapsulation

Encapsulation is defined as adding information around data before sending it. De-encapsulation is reverse, where it removes information around the data before sending it. The transport layer produces a segment, with the network layer taking the segment, adding an IP header to produce a packet. In my own words it's packaging the data with a "from" and "to" towards the network layer. Data Link layer takes the packet and adds a MAC header/trailer to produce a frame, then Physical layer converts the frame into bits for transmission.

8. Client-Server Model & Fast Food Analogy

A client is usually a device or something that sends a query, a request to change something. A server is a responder for the client that interprets and sends the appropriate data back to the client to answer the query or a request. A request occurs from the client → server (client asks a specific query of data to server) while a response occurs from server → client (server relays necessary data to client).

A client-server application example in the real-life world is fast food drive-thrus. The client, the customer, will request an order of food, with the server being the individual who takes the order and relays the information to get the food prepared and ready to pick up. The request is the food orders. The response is the food, which is the data that will be sent back to the client.

9, 10 & 11. Structured Cabling & Infrastructure

In order: Laptop → Wall jack → patch panel → Switch/IDF → Backbone Cabling → MDF → Demarc → ISP

The MDF, a main distribution frame, acts as the network's main hub and connects to the ISP. IDFs, also known as intermediate distribution frames, are mini-hubs that branch from the MDF, acting as extended network coverages for devices. Devices will connect to the nearest IDF. The demarc is the service provider handoff, responsible only for the connection into the building, acting as the handoff/boundary point between the ISP and the organization's own cabling/network.

Horizontal UTP cabling is designed to run from the patch panel to the wall outlet with the maximum permanent link distance of 90 meters. Backbone cabling connects the IDF back to the MDF, typically running between floors of a building, like an elevator.

14, 16 & 17. Home Network Topology & Practical Diagnostics

Home Topology: Netgear R7000P Router / Motorola MB7621 Modem / End Devices: MacBook (Wi-Fi), iPhone (Wi-Fi), Desktop PC (wired via powerline/Ethernet). Considering that everything branches out from one router, this matches the star topology.

Ping Test: 127.0.0.1 represents my local machine, my MacBook’s. Specifically, it tests that my machine's own network stack is functioning without sending anything to the network. Both pings got 100% replies with 0% packet loss. For the first ping, it took 0.2 milliseconds, which is essentially instant, as it never leaves my machine, compared to the UCF website, which took 41 milliseconds because it has to travel outside the UCF network.

Traceroute Analysis: Amazon had been cut off around hop 11 and UCF was cut off around hop 9, making it 11 hops with Amazon and 9 hops with UCF. A hop represents one router the packet passes through on its way to the destination. Both have identical hops from 1 to 7, but then they diverge around hop 8, where Amazon goes to CloudFront and UCF appears to go through the MSN routers before reaching its network. The asterisks mean that a hop didn't respond within the timeout window due to network congestion or possibly a router configured to not reply to the traceroute probes, even though traffic is flowing through it.

19. Wireshark 3-Pane Interface
  • Top pane (Packet List): The scrolling table which contains the number, time, source, destination, the protocol, the length, and information. One row per packet captured.
  • Middle pane (Packet Details): Shows each packet layer by layer, which is the frame, the Ethernet, and then the Internet Protocol and so on and so forth. In my case, it's breaking down frame 1, which is Ethernet II source and destination MAC addresses and then the IPv4 addresses and then IGMP.
  • Bottom pane (Packet Bytes): Shows the packet bytes. It simply shows the raw binary or hex behind it. It also has an ASCII translation on the right side.
